# Atlas 产品与界面设计

## 1. 产品定义

Atlas 不是另一个管理后台，也不是外部应用链接列表。它是所有工作应用之上的统一工作台：

- 用户从 Atlas 发现应用、搜索能力、继续最近的工作。
- Hermes、Chaos、Zwei 等应用保持独立部署、独立路由和独立业务上下文。
- Atlas 提供跨应用一致的身份、入口、搜索、最近访问与返回路径。

一句话定位：**一个入口，抵达所有工作空间。**

## 2. 产品模型

```text
Atlas Workspace
├── 全局层：身份 / 应用启动器 / 搜索 / 最近访问
├── Hermes：身份与访问
│   └── 域 / 应用 / 服务 / 关系 / 组
├── Chaos：消息与文件
│   └── 邮件模板 / 邮件发送 / 文件
└── Zwei：菜谱业务
    └── 菜谱 / 收藏 / 推荐 / 标签
```

Atlas 只管理“去哪里”和“如何回来”，不复制各应用内部的业务导航。跨域应用默认在当前标签页打开，让 SSO 和浏览器历史保持连续；用户可以通过系统快捷方式在新标签页打开。

## 3. 信息架构

### Atlas 首页

1. **平台栏**：Atlas 标识、工作台入口、全局搜索、通知和用户菜单。
2. **欢迎与启动器**：一句明确的产品文案，以及可点击、可键盘唤起的搜索入口。
3. **最近访问**：最多展示 6 个最近打开的应用能力，帮助用户继续工作。
4. **全部应用**：应用级介绍、状态、主入口和高频能力入口。

### 外部应用

1. 保留应用自己的主导航，不在 Atlas 首页模拟完整菜单。
2. 左上角应用标识应升级为“Atlas / 当前应用”切换器。
3. 所有应用共享 `Cmd/Ctrl + K`，搜索结果可以跨应用跳转。
4. 跨应用跳转前保留当前应用的路由和筛选状态；浏览器返回应可恢复现场。

## 4. 核心交互

### 全局启动器

- `Cmd/Ctrl + K` 从任意页面打开。
- 同时搜索应用名、应用说明和能力名称。
- 支持方向键移动、Enter 打开、Escape 关闭。
- 结果明确标识所属应用，避免同名能力造成误跳转。
- 无结果时提供可执行建议，不展示空白面板。

### 最近访问

- 访问记录存储为 `appId + capabilityId + visitedAt`，不保存敏感业务参数。
- 最近访问是个人本地体验，后续可以在登录账户下跨设备同步。
- 只记录用户主动打开的目标，不把页面刷新计为一次新访问。

### 应用卡片

- 卡片主操作打开应用首页。
- 高频能力作为独立的深链接，点击区域至少 44px。
- 应用色只用于图标、状态和轻量背景，不用于大面积文字或装饰。
- 外部跳转使用一致的箭头与说明，避免用户误以为是 Atlas 内部路由。

## 5. 视觉系统

### 设计性格

关键词：**清晰、克制、可靠、带一点情绪感**。

- 采用 Swiss / minimal 工具型界面，不使用渐变、玻璃拟态和装饰性发光。
- 使用 4/8px 间距体系；页面最大宽度 1200px。
- 平台表面只使用蓝白主系统，减少 Ant Design 默认后台感。
- 阴影只表达层级，边框负责大部分区域分隔。

### 色彩

| Token             | Light     | 用途               |
| ----------------- | --------- | ------------------ |
| `--atlas-primary` | `#2557d6` | 平台主操作、焦点环 |
| `--atlas-ink`     | `#15233b` | 主文字、品牌标识   |
| `--atlas-muted`   | `#5e6b82` | 次级说明           |
| `--atlas-canvas`  | `#f5f8fe` | 页面背景           |
| `--atlas-surface` | `#ffffff` | 卡片、浮层         |
| `--atlas-border`  | `#dce5f2` | 边框、分隔线       |

应用识别色使用情绪化而非纯正的基础色：

- Hermes：皮革与工艺感的烧橙 `#b94e20`，表达秩序、信任与边界。
- Chaos：风暴与工业感的灰 `#545d6b`，表达在混乱中建立结构。
- Zwei：番茄与香料感的暖红 `#b83f37`，表达温暖、鲜活与食欲。

应用色只用于品牌识别；成功、警告和错误状态仍使用独立语义色。

### 字体与图标

- 字体优先 Inter，中文回退到 PingFang SC / Microsoft YaHei / 系统字体。
- 标题 600–700，正文 400–500；不使用过多大写标签。
- 统一使用 Ant Design Icons 与自有 SVG 标识，结构图标不使用 Emoji。
- 数字、快捷键和标识符使用等宽数字特性。

### 动效

- Hover / focus / press 使用 150–220ms。
- 只动画 `opacity` 和 `transform`，不通过位移制造布局抖动。
- 启动器用淡入和小幅缩放表达层级；必须尊重 `prefers-reduced-motion`。

## 6. 响应式与无障碍

- 375px：单列应用，隐藏非必要平台栏文字，搜索入口保持可见。
- 768px：最近访问与应用卡片使用两列。
- 1024px 以上：三列应用，最大内容宽度 1200px。
- 所有交互元素具备可见焦点环和可读的 `aria-label`。
- 正文对比度至少 4.5:1；图标和边界状态至少 3:1。
- 键盘顺序与视觉顺序一致，提供“跳到主要内容”的 skip link。

## 7. 应用清单协议

Portal 不应在页面组件里散落外链。每个应用通过统一 manifest 注册：

```ts
interface AtlasAppManifest {
  id: string
  name: string
  description: string
  origin: string
  homePath: string
  brand: { color: string; tint: string; icon: ReactNode }
  capabilities: Array<{
    id: string
    name: string
    path: string
    keywords?: string[]
  }>
}
```

后续 manifest 可以由网关或服务注册中心下发，Portal 无需发版即可增加应用。

## 8. 迭代顺序

### Phase 1：建立工作台

- 重构 Portal 首页、平台栏、应用卡片和响应式布局。
- 建立应用 manifest 与最近访问。
- 实现可用的全局启动器。

### Phase 2：统一平台壳

- 在共享 UI 包增加 Atlas 应用切换器。
- 统一 Hermes、Chaos、Zwei 的 Header、页面间距、列表和表单层级。
- 消除各应用重复的主题配置，收敛为语义 token。

### Phase 3：跨应用能力

- 搜索接入真实业务数据和权限过滤。
- 最近访问同步到账户。
- 增加应用健康状态、收藏和个性化排序。

## 9. 明确不做

- 不用 iframe 拼装外部应用。
- 不使用浏览器式可关闭 Tab；跨 origin 的状态恢复和标签管理会制造伪桌面复杂度。
- 不在首页堆砌没有行动价值的统计图表。
- 不为了“高级感”使用玻璃拟态、渐变、发光和持续悬浮动画。
